🌧️ RainReady FlowSense

Multilingual Agentic-AI Civic Platform for Bengaluru

Converts citizen flood reports into verified hyperlocal alerts, safer route guidance and coordinated civic response — in under 5 minutes.

React 18 TypeScript Vite Tailwind CSS v3 Zero backend 🔬 Prototype · Simulated Data

Problem Statement

Bengaluru's annual urban flooding causes ₹500+ Cr in economic loss and puts millions of residents at risk. When waterlogging occurs, there is no fast, verified, multilingual civic alert system for residents, delivery workers, or students.

  • Manual hazard verification takes 30+ minutes
  • No deduplication — citizens receive flood of duplicate reports
  • No risk scoring or severity prioritisation
  • No safer route guidance for two-wheelers and pedestrians
  • No coordination pipeline for BBMP response tasks
Target: Reduce time to identify and broadcast a verified flood hazard from ~30 minutes to under 5 minutes. (Prototype target — not measured field data.)

Solution Overview

RainReady FlowSense is a two-module civic platform:

ModuleDescription
Community ReportsCitizens report flooding → AI analyses → human reviewer approves → alert broadcast + route + task
FlowSenseSimulated mobility telemetry → anomaly detection → agentic pipeline → emergency routing

Target Users

  • 🏠 Bengaluru residents and commuters
  • 🏍 Students and delivery workers (two-wheeler safety)
  • 🏘 Resident Welfare Associations (RWAs)
  • 🤝 Community volunteers
  • 🏛 Civic coordinators (BBMP response)

Features

1. Public Reporting

  • Multilingual form: English, ಕನ್ನಡ (Kannada), Hinglish
  • 5 incident types: Waterlogging, Flood, Blocked Drain, Pothole, Traffic Hazard
  • Optional anonymous reporting
  • Optional photo upload (local objectURL — no server)
  • Demo seed button: "Load HSR Layout Flood Report"
  • Full field validation with accessible error messages

2. Report Understanding Agent

  • 5-stage animated pipeline: Observe → Understand → Verify → Assess → Recommend
  • Extracts: incident type, location, severity, depth, confidence, duplicates
  • Demo: 92% confidence, HIGH severity, knee-deep depth, 4 duplicate reports

3. Duplicate & Verification Agent

  • Groups similar reports by location and incident type
  • Displays duplicate count and corroboration strength
  • Verification states: Pending → Verified / Rejected

4. Risk Scoring

  • Transparent 0–100 score with factor breakdown
  • Factors: severity, depth, traffic exposure, duplicate count, nearby vulnerable places, confidence
  • Labelled as prototype metric — not an official emergency prediction

5. Human Review Dashboard

  • Reports with risk ≥ 75 require human approval before broadcast
  • Reviewer sees: full report, AI explanation, duplicate count, risk score, route preview
  • Actions: Approve, Reject, Request More Info
  • Confirmation step before broadcast

6. Alerts

  • Green (info) / Amber (caution) / Red (danger) visual levels
  • Affected area, time, severity, what to do / avoid
  • Human verification status shown
  • People notified count

7. Safer Route Guidance

  • Unsafe road clearly labelled
  • Safe alternative with estimated detour time
  • Demo: Avoid HSR Layout Underpass → Use 27th Main Road (+8 min)

8. Response Coordination

  • Auto-created BBMP task on alert approval
  • Task status flow: Open → In Progress → Resolved
  • Reviewer notes timeline
  • Resolution closes alert and updates dashboard metrics

9. FlowSense Telemetry Module

  • Simulated real-time road condition detection
  • Rain simulation engine with speed degradation model
  • 8-phase agentic detection pipeline
  • Emergency vehicle routing
  • All data labelled: "Simulated aggregated mobility telemetry"

10. Dashboard

  • 6 KPI cards: Active Alerts, Reports Received, Verified, Duplicates Removed, Avg Response, Resolved
  • Neighbourhood risk summary (HSR Layout, Koramangala, Whitefield, Yelahanka, Rajajinagar)
  • Recent reports list and active alerts panel
  • Agentic pipeline visualisation

Privacy & Safety

Not a replacement for emergency services. In an emergency, call 112.
  • Reporter identity is never shown in public alerts
  • Location is neighbourhood-level only — no exact addresses stored
  • Photos are stored as browser-local objectURLs — never uploaded to any server
  • High-severity alerts require human approval before broadcast
  • Low-confidence reports (<70%) are never auto-broadcast
  • FlowSense uses aggregated road data — no individual vehicle tracking

Mock Data Limitations

  • All data is simulated — no real BBMP API, no live weather feed, no real-time traffic
  • FlowSense telemetry is generated by a client-side random simulation
  • Image uploads use browser objectURL (cleared on page refresh)
  • State is held in React Context — cleared on browser refresh
  • "Reduce response time to under 5 minutes" is a prototype target, not field-measured data
  • No SMS, push notification, or email integration
