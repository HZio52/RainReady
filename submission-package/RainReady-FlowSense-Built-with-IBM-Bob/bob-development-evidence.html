RainReady FlowSense · 10-Phase Development Story

This document records how IBM Bob was used as the development assistant throughout this prototype. All claims are honest. No live IBM AI services run inside the app at runtime.

Honest disclosure: IBM Bob was used as a coding assistant — generating code, debugging, reviewing accessibility and privacy decisions. The AI shown inside the prototype app is a client-side simulation, not a live IBM service.

Phase 1 — Problem Decomposition

1
Breaking down the civic problem
Planning

Bob was given the full Bobathon problem statement and asked to decompose it into implementable engineering modules.

What Bob produced

Phase 3 — Agent Workflow Design

3
7-stage agentic pipeline
AI Design

Bob defined the Observe → Understand → Verify → Assess Risk → Recommend → Coordinate → Follow Up pipeline and made it visible in the UI.

Design choices

  • Each stage is shown to the user during processing — no black-box AI
  • Human review gate at stage 4: risk ≥ 75 requires approval
  • Decision trace panel explains what the AI observed, inferred, and why
  • Confidence score shown with bar visualization, not just a number

Phase 6 — Bug Fixing

6
3 critical bugs identified and fixed
Debugging
Bug 1: Blank page crash
JSX icon functions defined inside a const array at module scope in Sidebar.tsx — React crashed before render.
Fix: Replaced all SVG JSX components with plain emoji strings — zero render overhead, same visual result.
Bug 2: PostCSS crash
surface: { 0: '#ffffff' } in tailwind.config.js — Tailwind v3 cannot generate utilities from a 0 numeric key.
Fix: Removed the 0 key entirely. Replaced with surface-50 and surface-100 named keys.
Bug 3: Stale import
useFlow was imported but unused in App.tsx — TypeScript error blocking build.
Fix: Removed the unused import. TypeScript build passes with 0 errors.

Phase 7 — Accessibility Review

7
ARIA, keyboard nav, mobile-first
Accessibility

Bob performed a full accessibility audit and implemented improvements.

Improvements added

  • ARIA labels on all icon-only buttons and form fields
  • Focus rings on all interactive elements (focus:ring-2 focus:ring-blue-500)
  • Keyboard navigation on custom controls (file upload zone, incident type buttons)
  • aria-pressed on toggle buttons, aria-describedby on error messages
  • Reduced-motion support: @media (prefers-reduced-motion) suppresses animations
  • High-contrast status indicators: colour + text label, never colour alone
  • Mobile-first layout with 44px minimum touch targets

Phase 8 — Privacy Review

8
Privacy safeguards and disclosures
Privacy

Bob reviewed all data flows and identified privacy considerations for a civic platform.

Privacy decisions implemented

  • Reporter identity (reporterAlias) is never shown in public alerts — only neighbourhood
  • Exact location is captured as neighbourhood-level only — no home address stored
  • Image upload uses browser objectURL — no server upload, no photo persistence
  • Anonymous reporting supported — alias is set to "Anonymous" in state
  • FlowSense telemetry uses aggregated road segments, never individual vehicle tracking
  • 50-sample minimum threshold before any anomaly is flagged
  • Privacy & Safety page accessible from every page footer
